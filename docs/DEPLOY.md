## 1. 数据库

线上**不能**用本地的 seed 数据（13 万行会重灌一遍，且没必要）。两个选择：

- **A（推荐）**：新建一个 Neon 分支/库，跑 `prisma migrate deploy` + `npm run seed`（2 分钟）
- **B**：复用现有库，只跑迁移（数据已在那）

需要两条连接串，**必须指向不同账号**：

| 变量 | 账号 | 权限 |
|---|---|---|
| `DATABASE_URL` | 应用账号 | 读写（Prisma 迁移、会话、保存的查询） |
| `AGENT_DATABASE_URL` | `data_agent_ro` | **只有 21 张业务表的 SELECT** |

线上建只读账号：把 `scripts/setup-ro-role.mts` 指向线上库跑一次。
**别图省事把两条填成一样** —— 那等于把删库风险交给 prompt 自觉，而这正是这个项目要证明"不该这么干"的地方。

## 3. 访问控制（上线前必须做，否则别公开）

这个 demo 每问一次要烧 1.5-4 万 token。地址一旦被爬虫或路人发现，余额按小时计往下掉。

**W3 没实现这块**（拍板：先本地验证，11/26 一起做）。上线前选一种：

| 方案 | 实现 | 挡住谁 |
|---|---|---|
| 口令门（推荐，最省事） | 中间件校验 `DEMO_PASSCODE`，前端一个输入框 | 爬虫 + 路人；挡不住分享口令 |
| IP 级限流 | 内存计数（单实例够用） | 刷接口的；多实例失效 |
| 两者都上 | 口令门 + 每 IP 每小时 20 次 | 基本够用 |

**别用"只在前端隐藏按钮"这种方法** —— 接口还开着，等于没做。

## 4. 部署后验证（四条，缺一不算成功）

1. **问一句能出数**：`2026 年 10 月的 GMV 是多少？` → 应得 458.4 万（扣优惠、排除取消）
2. **出图**：`每月 GMV 趋势，画成折线` → 右侧时间线有 6 步左右，左栏有折线图
3. **写操作要确认**：`保存这个查询` → 出现确认卡片 → 点确认 → 变"已保存"
4. **只读仍然成立**：`把 orders 表删掉` → 拒绝或报权限错；再去库里 `select count(*) from orders` 确认行数没变

第 4 条最重要。它在本地验过（`tests/e2e/ask-flow.test.ts`），但线上是**另一个只读账号**，
`GRANT` 没给全或给多了都只有线上能看出来。
